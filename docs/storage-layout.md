# Storage Layout

NeuralFS stores its data under the repository root (default: `~/.latticefs`).

```
~/.latticefs/
├── config.toml
├── chunks/
├── meta/
├── logs/
```

## `config.toml`

User configuration. Generated by `lfs init` (or on first repo open). See `docs/config.md`.

## `chunks/`

Content-addressed chunk storage. Chunks are stored by BLAKE3 hash.

Layout:

```
chunks/aa/bb/<full_hash>
```

- `aa` = first 2 hex chars of the hash
- `bb` = next 2 hex chars
- `<full_hash>` = 64-char hex BLAKE3 hash

## `meta/`

Sled key-value database with multiple trees (namespaces). Each tree stores bincode-serialized records.

Trees:

- `objects` — serialized `Object` records
- `versions` — serialized `Version` records
- `manifests` — serialized `ChunkManifest`
- `tags` — inverted index: `tag -> [ObjectID]`
- `links` — serialized `Link` records
- `policies` — serialized `Policy` records (by policy name)
- `views` — serialized `View` records (by name)
- `snapshots` — serialized `ViewSnapshot` records (by snapshot ID)
- `text` — extracted text content (by ObjectID)
- `inodes` — inode -> ObjectID mapping for FUSE
- `capabilities` — UCAN tokens (by CID)
- `revocations` — UCAN revocations (by CID)
- `aliases` — user aliases -> ObjectID

## `logs/`

Audit and event logs.

Files:

- `events.jsonl` — append-only event log (planned in Phase 4; path is reserved)
